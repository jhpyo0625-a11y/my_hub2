# MyHerb — frontend2

영양제 섭취 리포트 화면과, 그 화면에 붙는 로컬 서버입니다.
화면과 API 가 **같은 주소에서 함께** 돌기 때문에 CORS 설정이 필요 없고,
`uv` 하나만 있으면 명령 두 줄로 뜹니다.

```
uv sync
uv run server.py        →     http://localhost:3000
```

---

## 1. 실행하기

### 1-1. uv 설치 (한 번만)

이미 있으면 건너뛰세요. `uv --version` 으로 확인할 수 있습니다.

```bash
# macOS · Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

> 파이썬을 따로 깔 필요는 없습니다. 이 폴더의 `.python-version` 에 3.12 로
> 적어 두었고, 없으면 `uv` 가 알아서 받아 옵니다.

### 1-2. 의존성 맞추기

```bash
cd frontend2
uv sync
```

`.venv/` 가 만들어지고 `fastapi` 와 `uvicorn` 이 설치됩니다.
`uv.lock` 이 함께 있으므로 누가 언제 받아도 같은 버전이 깔립니다.

### 1-3. 서버 띄우기

```bash
uv run server.py
```

브라우저에서 **http://localhost:3000** 을 엽니다.

| 하고 싶은 것 | 명령 |
|---|---|
| 그냥 실행 | `uv run server.py` |
| 포트 바꾸기 | `PORT=8080 uv run server.py` |
| 코드 고치면 자동 재시작 (개발용) | `uv run uvicorn server:app --reload --port 3000` |
| API 문서 열어 보기 | 서버를 띄운 뒤 http://localhost:3000/api/docs |

멈출 때는 `Ctrl + C` 입니다.

## 2. 화면 흐름

로그인은 **아무 이메일과 비밀번호나** 넣으면 그대로 통과합니다. (§5 참고)

```
   메인 화면 ──[로그인]──▶ 메인 화면 (로그인 상태)
                              │
                              ├──[입력 시작하기]──▶ 등록 화면 ──[결과 보기]──▶ 결과 화면
                              │                    (대화형/폼)                    ▲
                              │                                                  │
                              └──[지난 리포트 보기]──▶ 목록 화면 ──[다시 보기]───┘
```

각 화면에 들어갈 때 서버를 부릅니다.

| 화면 | 들어갈 때 부르는 것 | 무엇을 받아 그리는가 |
|---|---|---|
| 메인 | `GET /api/me` | 로그인한 사람 이름 (상단바) |
| 로그인 | `POST /api/login` · `POST /api/signup` | 사용자 정보 → 세션에 저장 |
| 등록 | `GET /api/draft` | 전에 입력하다 만 내용 (입력 중 `PUT /api/draft` 로 자동 저장) |
| 등록(사진) | `POST /api/exam-image` | 검진표 사진에서 읽은 값 → 자동 채움 (§2-B) |
| 결과 | `POST /api/analyze` | 입력한 내용으로 계산한 리포트 |
| 목록 | `GET /api/reports` | 그 사용자가 지금까지 분석한 목록 + 입력 요약 |
| 상세 | `GET /api/reports/{id}` | 그 리포트 하나의 전체 내용 |
| 목록(삭제) | `DELETE /api/reports/{id}` | 카드 안에서 한 번 더 확인한 뒤 지웁니다 |

**등록 화면은 두 가지 방식이 있습니다.** 화면 위 토글로 언제든 바꿀 수 있고,
어느 쪽으로 입력하든 채워지는 값은 같습니다.

- **대화로 입력** — 질문에 하나씩 답합니다. 답한 말풍선의 '수정' 을 누르면 그 질문만 다시 답할 수 있습니다.
- **폼으로 입력** — 필요한 항목만 골라 채웁니다.

## 2-B. 검진표 사진으로 한 번에 채우기

대화 화면 입력칸 위에 **＋ 검진표 이미지 등록** 버튼이 늘 떠 있습니다.
건강검진 결과지 사진을 올리면 서버가 읽어서 한꺼번에 채우고,
**그렇게 채워진 질문은 다시 묻지 않습니다.**

```
＋ 클릭  →  사진 선택  →  POST /api/exam-image  →  읽은 값을 입력에 병합
                                                      ↓
                              이름·나이·성별·검진일·검진 수치가 채워지고
                              그 질문들은 건너뛴 채 '식사 평균 계산할까요?' 부터 이어집니다
```

- **이미지 파일만** 받습니다. 파일 선택 창에서도 이미지만 보이고, 고른 뒤에도
  화면이 한 번, 서버가 파일 앞머리 바이트로 한 번 더 확인합니다.
  확장자를 `.png` 로 바꿔도 통과하지 못합니다.
- 사진에서 온 답은 말풍선에 **'검진표에서'** 라고 표시되고 색이 다릅니다.
  잘못 읽힌 값은 그 말풍선의 **수정** 으로 바로 고칠 수 있습니다.
- 이미 직접 답하신 이름·나이·성별은 사진이 밀어내지 않습니다.

### 판독은 누가 하나요

`vision.py` 의 `read_exam_image()` 하나가 합니다. 두 가지 방식이 있고
환경변수로 갈립니다.

| 환경 | 동작 |
|---|---|
| `ANTHROPIC_API_KEY` 가 있을 때 | Claude 에 이미지를 보내 실제로 판독합니다 |
| 없을 때 (기본) | **예시 판독**. 사진마다 견본 넷 중 하나를 고릅니다 |

```bash
# 실제 판독을 켜려면
ANTHROPIC_API_KEY=sk-ant-... uv run server.py
```

> ⚠️ 예시 판독일 때는 화면 말풍선 맨 앞에 **"예시 판독입니다(실제 사진을 읽은
> 결과가 아니에요)"** 라고 분명히 적힙니다. 판독한 척하지 않습니다.
>
> 예시 판독은 아무 값이나 돌려주는 게 아니라 **사진 내용의 해시**로 견본을
> 고릅니다. 그래서 같은 사진은 늘 같은 결과가 나오고, 다른 사진을 올리면
> 다른 결과가 나옵니다 — 자동 채움과 질문 건너뛰기를 제대로 확인할 수 있습니다.
>
> API 키를 쓰는 실제 판독 경로는 키가 없는 환경에서는 실행되지 않으므로,
> 처음 켜실 때 응답을 한 번 눈으로 확인해 보시기 바랍니다.

실제 모델을 다른 것으로 바꾸려면 `vision.py` 의 `_read_with_claude()` 하나만
고치면 됩니다. 어떤 모델을 쓰든 결과는 `_clean()` 을 반드시 통과시키세요 —
모델이 엉뚱한 키나 말도 안 되는 값을 뱉어도 그대로 입력에 들어가면 안 됩니다.

## 2-C. 결과 화면 읽는 법

성분 카드는 **한 화면**입니다. 예전에는 '권장 대비'와 '상한 대비' 탭이
나뉘어 있었는데, 권장량과 상한은 같은 눈금자 위의 두 지점일 뿐이라 나눌
이유가 없었습니다. 오히려 탭을 오갈 때마다 같은 카드의 숫자만 바뀌어서
지금 보는 게 어느 기준인지 헷갈렸습니다.

```
   반원 게이지 :  권장량 대비 몇 %인지

   막대        :  │████████░░░░│      │        │
                  0          권장    상한      끝
                     ▲ 영양제   ▲ 식사 추정
```

**막대의 오른쪽 끝은 상한이 아닙니다.** 상한 눈금 뒤에 자리를 남겨 두어서,
상한을 넘은 값이 눈금을 지나 뻗어 나갑니다. 살짝 넘었는지 두 배로 넘었는지가
한눈에 구분됩니다. (예전에는 넘으면 막대를 통째로 빨갛게 채워서 둘이
똑같아 보였습니다.)

- 상한을 넘으면 막대 색이 빨강으로 바뀝니다.
- 마그네슘처럼 권장량과 상한이 같은 성분은 눈금 글자가 **'권장·상한'** 하나로 합쳐집니다.
- 상한이 정해지지 않은 성분(비타민 B1 등)에는 상한 눈금이 없습니다.

### 지난 리포트 목록

카드 한 장에 **언제 · 누가 · 무엇을 넣었는지 · 결과가 어땠는지** 가 순서대로
들어갑니다. 날짜와 배지만 있으면 같은 날 여러 번 돌린 리포트를 열어 보기
전에는 구분할 수 없기 때문입니다.

**삭제** 는 카드 안에서 한 번 더 확인한 뒤 지웁니다 — 브라우저 기본 확인창은
화면 밖에 떠서 무엇을 지우는 중인지 보이지 않습니다.

## 3. 폴더 구조

```
frontend2/
├── README.md            ← 지금 보고 계신 파일
├── pyproject.toml       의존성 (fastapi · uvicorn)
├── uv.lock              잠긴 버전. 손대지 마세요
├── .python-version      3.12
│
├── server.py            ★ 로컬 서버. 엔드포인트 열한 개 + 화면 서빙
├── analyze.py           ★ 판정. Input → Report
├── exam.py              건강검진 판정기준 (별표 4)
├── standards.py         성분 기준표 · 상호작용 규칙        ← 교체지점
├── vision.py            검진표 사진 판독 · 이미지 검증     ← 교체지점
│
├── static/              서버가 브라우저에 내려주는 것 (자동 생성물)
│   ├── Live.html
│   ├── live-app.js      판정 코드가 한 줄도 없습니다
│   └── styles.css
│
└── src/                 화면 원본. 고칠 때는 여기를 고칩니다
    ├── report.html
    ├── app.js           목업 판정이 들어 있는 개발용
    ├── styles.css
    └── build-live.js    src/ → static/ 변환기
```

### 왜 `src/` 와 `static/` 이 나뉘어 있나요

이 서비스의 원칙은 하나입니다. **화면은 판단하지 않습니다.**

"이 성분이 부족한가", "상한을 넘었는가", "이 약과 부딪히는가" 는 전부 서버가
정합니다. 그래서 브라우저에 내려가는 `static/live-app.js` 에는 판정 코드가
**한 줄도 없습니다.** 입력을 모아 보내고, 돌아온 결과를 그리기만 합니다.

- 기준값이 바뀌어도 **서버만 고치면 됩니다.** 화면을 다시 배포할 필요가 없습니다.
- 건강에 관한 판단이 사용자 브라우저에 노출되지 않습니다. 검증·감사할 지점이 서버 한 곳으로 모입니다.

`src/app.js` 는 서버 없이 브라우저 안에서 판정을 흉내 내는 **개발용**입니다.
`build-live.js` 가 거기서 목업 부분만 걷어내 `static/` 을 만듭니다.

## 4. 화면을 고치려면

`static/` 안의 파일은 **자동 생성물입니다. 직접 고치지 마세요.** 다음 빌드 때 덮어써집니다.

```bash
# 1. src/app.js · src/report.html · src/styles.css 를 고칩니다
# 2. 다시 만듭니다
cd src
node build-live.js
# 3. 브라우저 새로고침 (서버는 재시작하지 않아도 됩니다)
```

> 이 단계에만 Node.js 가 필요합니다. `static/` 은 이미 만들어져 있으므로,
> **서버를 띄워서 쓰기만 할 때는 Node 없이 uv 만 있으면 됩니다.**

판정 기준을 고칠 때는 Node 가 필요 없습니다. `standards.py` 나 `exam.py` 를
고치고 서버만 재시작하면 됩니다.

## 5. 로그인이 무조건 성공합니다

숙제 요구사항에 따라 **비밀번호를 검사하지 않습니다.** 어떤 이메일과
비밀번호를 넣어도 그 이메일의 사용자로 로그인됩니다.

- 이메일마다 데이터가 따로 쌓입니다. 다른 이메일로 로그인하면 목록이 비어 있습니다.
- 이름을 적지 않으면 이메일 앞부분을 이름으로 씁니다. (`byeol@example.com` → `byeol`)
- 이메일까지 비워도 막지 않고 손님 계정으로 받습니다.

실제 검증을 넣을 때는 `server.py` 의 `_login_always_ok()` 안쪽만 고치면 됩니다.
**화면 코드는 한 줄도 건드릴 필요가 없습니다.** 실패를 `400` 으로 내려보내면
화면이 그 문구를 사용자에게 그대로 보여 줍니다.

> ⚠️ `401` 은 이 서비스 전체에서 **"세션이 없거나 끊겼다"** 는 뜻으로만 씁니다.
> 로그인 실패에 `401` 을 쓰면 화면이 그것을 세션 만료로 읽고 재로그인 창을
> 다시 띄웁니다. 사용자는 같은 창이 계속 뜨는 것만 보게 됩니다.
> **로그인·회원가입 실패는 반드시 `400` 입니다.**

## 6. 사용자 정보는 세션에 어떻게 저장되나요

두 곳에 있습니다. **원본은 서버**, 브라우저에 있는 것은 사본입니다.

### 서버 (원본)

로그인에 성공하면 서버가 세션을 만들고 쿠키를 내려 줍니다.

```
Set-Cookie: myherb_sid=<임의의 긴 문자열>; Path=/; HttpOnly; SameSite=Lax; Max-Age=604800
```

화면은 모든 요청을 `credentials: 'include'` 로 보내므로 이 쿠키가 자동으로
함께 갑니다. `HttpOnly` 라서 자바스크립트는 이 값을 읽지 못합니다.

### 브라우저 (사본)

로그인 성공 시 받은 `{name, email}` 을 `sessionStorage` 에도 한 벌 둡니다.

```js
sessionStorage["myherb.user"] = {"name":"byeol","email":"byeol@example.com"}
```

**왜 두는가** — 새로고침했을 때 `GET /api/me` 응답이 올 때까지 상단바가 비어
있다가 이름이 뒤늦게 나타나는 깜빡임을 없애기 위해서입니다.

**그래서 이 값은 표시용입니다.** 이 값이 있다고 로그인된 것으로 치지 않습니다.
화면을 열 때 서버에 반드시 다시 물어보고, 서버가 아니라고 하면 사본도 함께
지웁니다. 브라우저 저장소는 사용자가 직접 고칠 수 있으므로 권한의 근거로
쓰면 안 되기 때문입니다.

### 직접 확인하는 법

1. 로그인한다
2. `F12` → **Application** 탭 → **Session Storage** → `http://localhost:3000`
3. `myherb.user` 키에 이름과 이메일이 들어 있습니다
4. 같은 화면의 **Cookies** 에 `myherb_sid` 가 있습니다 (값은 서버만 압니다)
5. 로그아웃하면 둘 다 사라집니다

`sessionStorage` 는 탭 하나에만 살아 있고, 탭을 닫으면 지워집니다.
저장소가 막힌 환경(시크릿 모드 등)에서는 사본 없이 동작합니다 — 이름이 조금
늦게 뜰 뿐 기능에는 지장이 없습니다.

## 7. API 열한 개

전부 `application/json; charset=utf-8` 입니다 (사진 올릴 때만 예외).
자세한 요청·응답 모양은 **'백엔드 연동 규격서'** 에, 실행 중인 서버의
문서는 http://localhost:3000/api/docs 에 있습니다.

| 메서드 | 경로 | 로그인 | 하는 일 |
|---|---|:---:|---|
| `GET` | `/api/bootstrap` | ✕ | 화면 열 때 한 번. 성분 이름 추천 목록 |
| `GET` | `/api/me` | ○ | 지금 로그인되어 있는지 |
| `POST` | `/api/signup` | ✕ | 회원가입 (무조건 성공) |
| `POST` | `/api/login` | ✕ | 로그인 (무조건 성공) |
| `POST` | `/api/logout` | ✕ | 로그아웃 |
| `GET` | `/api/draft` | ○ | 저장해 둔 입력값. 없으면 `null` |
| `PUT` | `/api/draft` | ○ | 입력값 저장 (입력이 멈추면 1.2초 뒤 자동으로) |
| `POST` | `/api/exam-image` | ○ | 검진표 사진 판독. **본문이 이미지 바이트 그대로** |
| `POST` | `/api/analyze` | ○ | ★ 판정. 성공하면 이력에 자동 저장 |
| `GET` | `/api/reports` | ○ | 지난 리포트 목록 (최신순, 요약 + 입력 정보) |
| `GET` | `/api/reports/{id}` | ○ | 지난 리포트 하나 (analyze 와 같은 모양) |
| `DELETE` | `/api/reports/{id}` | ○ | 지난 리포트 하나 지우기 |

오류 본문은 `{"message": "사용자에게 보일 한국어 문장"}` 입니다.

`/api/exam-image` 만 JSON 이 아니라 파일 바이트를 그대로 받습니다. 파일이
하나뿐이라 multipart 로 감쌀 이유가 없고, 그러면 서버에 의존성
(`python-multipart`)도 늘지 않습니다.

```bash
curl -b cookie.txt -H 'Content-Type: image/png' \
     --data-binary @검진표.png http://localhost:3000/api/exam-image
```

## 8. 알아 두실 점

### ⚠️ 성분 기준값은 검증되지 않은 예시입니다

`standards.py` 의 성분 기준표와 상호작용 규칙은 **예시**입니다.
실제 판단에 쓰면 안 됩니다. 그래서 화면 맨 위에 경고 띠가 계속 떠 있습니다.

검증된 출처(KDRI 등)로 교체한 뒤 `server.py` 의 `UNVERIFIED` 를 `False` 로
바꾸면 경고 띠가 사라집니다.

(건강검진 판정기준 `exam.py` 는 국가 건강검진 실시기준 [별표 4] 를 옮긴
것이지만, 고시가 개정되면 함께 고쳐야 합니다.)

### 데이터가 메모리에만 있습니다

서버를 끄면 가입한 계정도, 저장한 입력도, 쌓인 리포트도 전부 사라집니다.
DB 를 붙이려면 `server.py` 위쪽의 `SESSIONS · USERS · DRAFTS · REPORTS`
네 개를 바꾸면 됩니다.

올린 사진은 **저장하지 않습니다.** 판독에 쓰고 그 자리에서 버립니다.
건강검진 결과지는 민감정보라, 보관할 이유가 없으면 안 두는 편이 안전합니다.
보관해야 한다면 보관 기간과 파기 절차를 먼저 정하세요.

### 글꼴은 인터넷에서 받아 옵니다

본문 글꼴(Pretendard)을 CDN 에서 불러옵니다. 인터넷이 없으면 시스템 기본
글꼴로 나옵니다 — 생김새만 조금 달라질 뿐 동작에는 지장이 없습니다.
완전히 오프라인으로 쓰시려면 글꼴 파일을 `static/` 에 넣고
`src/report.html` 의 `<link>` 를 그 경로로 바꾼 뒤 다시 빌드하세요.

### 실제 서비스로 갈 때

이 서버는 확인용입니다. 그대로 배포하면 안 됩니다.

- [ ] 성분 기준값을 검증된 출처로 교체했는가
- [ ] 상호작용 규칙을 약사·의사 검토를 거친 자료로 교체했는가
- [ ] 교체한 뒤 `UNVERIFIED` 를 `False` 로 바꿨는가
- [ ] 검진표 판독을 예시가 아닌 실제 모델로 바꿨는가 (`vision.py`)
- [ ] 판독 결과를 사용자가 확인·수정하는 단계를 반드시 거치게 했는가
      (모델이 숫자를 잘못 읽어도 그대로 판정에 들어가면 안 됩니다)
- [ ] 로그인에 실제 검증을 넣었는가 (`_login_always_ok`)
- [ ] 비밀번호를 해시해서 저장하는가
- [ ] 데이터를 DB 에 저장하는가
- [ ] HTTPS 를 쓰고 쿠키에 `secure=True` 를 붙였는가
- [ ] 로그인 시도 횟수 제한을 두었는가
- [ ] 건강정보를 다루므로 보관 기간·파기 절차·접근 통제를 정했는가

> 마지막 항목은 기술 문제가 아니라 **법·제도** 문제입니다.
> 건강검진 결과와 복약 정보는 민감정보에 해당합니다.
> 실제 서비스 전에 개인정보 처리 방침과 동의 절차를 반드시 갖추세요.
