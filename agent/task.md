1. agent 해야 할 일들.
1) normalizer
a. ocr 안붙어 있음
b. over work 하는 부분 제거 필요. 
- 이 에이전트는 사용자가 입력한 정보를 우리 agent 에서 사용하기 위한 규격으로 가공하는 일만 해야 함.
- 현재 여기서 영양소 부족 및 경고를 판단하고 있으니 이 부분 제거 할 것.
- 마스킹 처리는 여기서 판단하지 않고 마지막에 사용자에게 노출 전에만 하면 됨.
2) planner
a. state 사용하도록 변경할 것.
- param 으로 데이터 주고 받지 말고, 가능하다면 state 를 주고 받아 해결 할 것. (부득이한 경우엔 param 던질 것.)
b. 툴 콜링하는 부분도 함수별로 인자를 하드 코딩 했는데 이 부분도 sys 프롬프트로 가이드를 주어 해결하거나, md 파일을 통해 가드레일을 형성해서 하거나 할 것. (툴 콜링을 여러 곳에서 한다면 md 파일로 작업하고 여기서만 쓰인다면 sys 프롬프트로 작업하는 것도 괜찮다고 생각함.)
c. 계획과 실행에서 사용할 공통 포맷을 위해 PlanStep 클래스를 생성했는데 사용하지 않고 있음. 불필요하다면 안써도 되는데 써야되는 상황이면 각각 포맷을 임의로 사용하지 않고 클래스 통해 사용하여 일관성을 줄것.
3) executor
a. state 사용하도록 변경할 것.
b. 계획과 실행에서 사용할 공통 포맷을 위해 PlanStep 클래스를 생성했는데 사용하지 않고 있음. 불필요하다면 안써도 되는데 써야되는 상황이면 각각 포맷을 임의로 사용하지 않고 클래스 통해 사용하여 일관성을 줄것.
4) reviewer
a. MAX_RETRIES 횟수는 .env 연동해서 사용할 수 있게 할 것.
b. PlanStep 클래스 참고 할 것.
5) aggregator
a. 통합의 역할을 하는 agent 로써 역할을 수행하고 있는지 점검 필요.
- 개인적으로 최종적으로 나와야 하는 json 규격이 이때 만들어져야 한다고 생각함.
6) compliance
- 규칙에 대해선 sys 프롬프트보단, md 파일을 통한 하네스 가드레일로 처리하는게 일관성이 있을 듯.
a. _render_html 부분은 프롬프트 템플릿으로 처리해 줄 것.
